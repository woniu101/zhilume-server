## 判定规则

- 已实现：界面、输入校验、接口与执行器存在。
- 集成通过：实际 Server/Worker 控制与文件传输通过；使用替代推理服务时必须明确标记。
- 真实样本通过：记录具体模型、规格、环境和输出，不能扩展为全部参数或全部机器已验证。
- 创作闭环通过：Studio 提交、执行、结果原位展示、画布保存与重新打开全部完成。Web 与 Windows 原生交互分别记录。

## 保存、任务与恢复

| 项目 | 当前行为 / 验收要求 |
|---|---|
| Worker 结果归档 | 素材、成功任务与节点结果记录在同一事务提交，之后再向 Worker 确认；四类真实 Python Worker 集成必须断言节点结果，而非只检查 job succeeded |
| 保存响应丢失 | 保留最后一次未确认写入；再次保存前读取 Server，只有内容确实等于该次写入才推进版本；其他窗口修改仍报告冲突 |
| 会话续期 | 自动续期成功通知工作区重试未保存内容；有效会话重连不主动轮换续期授权 |
| 切换 Server | 草稿按稳定身份隔离；异步准备之前固定提交目标，切换后的旧操作不能提交到新 Server |
| 迟到结果 | 用户修改、替换或删除目标后，结果进历史，不覆盖当前内容；普通连线不会自动触发下游 |
| Server 重启 | 本轮 H3 首帧任务已验证 Server 重启后原 attempt 恢复及结果归档；互联网请求结果未知时保持中断，不自动重复收费调用 |
| Worker 重启 | 丢失的执行 attempt 明确中断，允许手动重试；不能宣称模型进程支持断点继续推理 |
| 批量与 DAG | 已有显式依赖、取消、重试；本轮仅修复提交目的服务隔离，不扩展流程产品功能 |

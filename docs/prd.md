## 1. 文档约定与决策依据

本文汇总用户构想、后续讨论、Updream 实际交互调研及旧项目能力参考。优先采用用户后续明确的方向。

- **首期默认方案**：为使开发可执行而在本 PRD 中提出的具体规则，包括快捷键、状态、存储、发布边界和协议草案；不宣称这些细节已由用户逐项确认。开发以此为默认，涉及实质范围变化时更新本文。
- **后续候选**：不属于本期交付，不因出现在竞品或旧仓库中而自动纳入。
- **竞品观察**：仅代表调研时看到或操作得到的结果。未测试的竞品行为不作为事实；本文可以明确提出自己的产品规则。

本期不修改或复用 `zhihua-service`。其源码仅作为已有生成能力的参考，不是新系统的代码基础、兼容目标或功能上限。

## 2. 已确认的产品方向

1. Zhilume，中文名“织镜”，面向 AI 图片、视频、音频创作，以画布组织文本、素材、参考关系和创作结果。
2. Studio 参考 Updream 的基础节点与画布交互，当前范围为文本、图片、视频、音频四类节点以及素材管理。
3. 当前开发图片裁剪、拼图、宫格切分、视频截取与抽音轨，图片本地处理，视频 Web 走 Server、Electron 走本机。Qwen Image 2512 与 2.1 同期纳入能力设计，GPU 实测前告知用户。
4. Agent 节点、Agent 系统等在整体产品成熟后再考虑。
5. Studio 从开始支持 Web 和桌面可执行程序两种发布形态。
6. Server 独立于 Studio，支持服务部署和面向普通用户的可执行程序，并提供 Web 管理后台。
7. 生成后端由自主部署的 Server、Worker 承担。Worker 可部署到优云智算、AutoDL、其他 GPU 平台或用户自己的 GPU 主机。
8. 三个独立仓库、独立发布；Studio 不直接调用 Worker，Server 不承担 GPU 模型推理。
9. Studio 采用 React、TypeScript、Electron；Server 核心采用 Node.js、TypeScript，管理界面采用 React、TypeScript，桌面启动器采用 Electron。
10. Worker 采用 Python、`asyncio` 和 FastAPI/Uvicorn 接入层，运行 GPU 生成执行器并保留显式模拟能力。Server 主动连接 Worker，执行核心与 HTTP/WebSocket 路由分离。
11. Server 主动连接 Worker；Server 不需要公网地址。网络可达性由用户自行解决，不实现 SSH 隧道、组网或中继，也不提供配套工具入口或配置示例。
12. 优先本地开发三端流程，再进行远程 Worker 联调，最后按选定范围接入真实生成能力。
13. Studio 与 Server 首期支持深色、浅色和跟随系统。已确认视觉为“中性黑白灰主体＋少量雾蓝强调”，不采用大面积蓝色界面。

## 3. 产品目标与使用场景

### 3.1 用户与场景

| 用户／场景 | 需求 | 首期目标 |
|---|---|---|
| 普通创作者 | 不配置 Python 或模型也能整理创作素材 | 安装 Studio／Server，创建画布、导入素材、保存项目 |
| 自部署用户 | 浏览器和桌面端访问同一个创作服务 | 可配置 Server 地址；两种客户端读取同一项目 |
| 自有算力用户 | 将自己的 GPU 机器接入系统 | 首期使用模拟 Worker 验证注册、状态与任务接收 |
| 云 GPU 用户 | 计算机器可更换，项目与素材长期保留 | Worker 临时目录与 Server 长期资产分离 |
| 开发与验收人员 | 不启动 GPU 也能验证业务闭环 | 模拟成功、失败、取消、断线、重连与结果归档 |

### 3.2 首期成功标准

- 用户能够完成“建项目 → 添加四类节点 → 导入和编辑内容 → 连线／分组 → 入库 → 关闭并重新打开”的完整流程。
- 同一项目在 Studio Web 和桌面版显示一致的节点、内容、资产引用和连接。
- 无 Worker 时，项目、画布、素材管理和媒体播放仍然可用。
- 模拟 Worker 能执行真实的任务领取、输入下载、状态回报和结果上传；Studio 显示实际归档结果。
- Server 重启后项目、素材与任务记录仍存在；Worker 离线或停止不会造成项目素材丢失。
- Windows 普通用户无需全局安装 Node.js、Python 即可运行 Studio 与 Server 发布包。
- 本期验收不能被表述为真实模型推理、生产级多租户或所有云平台部署已验收。

### 4.4 本轮媒体处理规则

- 图片：浏览器 Canvas 读取原图像素，裁剪支持框选和精确坐标；宫格最多 8 × 8，余数像素分摊到边缘；拼图最多 16 张，可选顺序、列数、格尺寸、间距和背景色，保持每张图片完整比例。
- 拼图原图合计最多 6400 万像素；单张原图/输出最多 3200 万像素，输出边长最多 16384。拼图单格 64–2048 px、间隔 0–100 px；输出 PNG。
- 视频固定执行位置：Studio Web 提交 Server 后台任务，Studio Electron 主进程管理本机 FFmpeg 子进程。普通媒体不依赖 Worker 或 GPU，不提供自动选址、用户选址、Web 本地服务或 FFmpeg WASM。
- Server 与 Electron 复用 `@zhilume/media`。唯一源码位于 Server `packages/media`，通过版本化 npm tgz 发布到两个独立仓库，统一校验、格式、进度、取消和错误处理。
- 输入与输出各限 1 GiB，0 ≤ start < end ≤ 实际视频时长，最多 86400 秒。截取精确重编码 MP4 H.264/AAC；抽音轨输出 WAV PCM s16le；无音轨返回 `no_audio`。原素材保持不变。
- 发布包内置对应平台 FFmpeg，用户无需安装。初版提供 Windows x64 EXE，其他平台须对应构建验收。Server 固定媒体并发 1，关闭页面不影响后台任务。任务进度与项目管理请求独立。
- Electron 的图片和视频工具优先直接读取已导入本地原文件，经大小/SHA-256 校验后使用原路径；文件改变、移走或只存于远程 Server 时，下载到内容寻址缓存并显示下载进度。输出由主进程流式同步到 Server，再插入新节点。
- 桌面阶段：validating → downloading（按需）→ processing → syncing → succeeded；错误为 failed / sync_failed，取消为 cancelled。同步失败保留输出，重试仅上传，不重新转码；同步幂等标识防止重复资产。不承诺应用退出后恢复未同步结果。
- Web 状态：queued → running → succeeded / failed；运行中取消先为 cancel_requested，子进程退出后 cancelled；Server 停止或重启使活动任务 interrupted，可手动重试，排队任务恢复继续。真实 FFmpeg 进度，归档成功才显示完成。
- Electron 原图读取上限 64 MiB，图片仍在 renderer Canvas 处理；Web 图片仍在浏览器本地处理。图片预览后保存新节点或替换同类型结果；失败保留 Blob，可重试或下载。宫格一次插入，原资产不改写，画布操作可撤销。
- 结果保存来源资产 ID、操作、参数；图片宫格另存输出序号，Web 视频结果附 Job ID。
- 2512 只支持文生图，不混同 Edit2511；2.1 纳入文生图、指令编辑、多图参考和 RGBA。操作与模型分开，参考顺序必须保留；不支持的参数明确报错，不静默丢弃。
- `/image-models` 返回模型目录与在线执行配置。Worker 显式启用并通过只读检查后可试运行；模型仍标记 `awaiting_gpu_validation`，不将节点/文件存在当作推理验收。调度必须匹配 modelId、profileId、workflowRevision 和 operation；参考上限与尺寸来自执行配置，GPU 阶段单独验收。

## 5. 三端架构与技术边界

### 5.1 调用与存储关系

```text
Studio Web / Studio Desktop
             │ HTTPS API + 实时事件
             ▼
       Zhilume Server
       ├─ 项目与画布文档
       ├─ 长期资产与素材库
       ├─ 任务、能力和调度
       └─ Web Admin
             │ Server 主动建立连接；连接建立后双向传递控制消息
             │ Server 上传输入／下载结果；Worker 无回调 Server
             ▼
       Zhilume Worker
       ├─ asyncio 控制程序
       ├─ 模拟执行适配器（首期）
       └─ ComfyUI / Python 生成执行器
```

- Studio 仅保存 Server 地址、登录凭证和可清理的本地缓存，不成为长期素材唯一副本。
- Server 是业务状态与资产元数据的权威来源。Worker 仅持有执行需要的临时副本与恢复日志。
- Server 与 Worker 的控制协议传递语义任务、资产引用及参数，不传递任意可执行脚本或用户提供的 ComfyUI 图。
- Worker 内部模型目录、环境、工作流映射不向 Studio 暴露。
- 首期一个 Server 进程负责调度，支持至少两个模拟 Worker；不建立多 Server 调度集群。

### 5.2 技术选型

| 层 | 已确认／默认选择 | 实现约束 |
|---|---|---|
| Studio UI | React＋TypeScript；React Flow 作为画布默认方案 | 渲染、命令、素材选择器不直接依赖 Electron |
| Studio 平台层 | BrowserPlatform／ElectronPlatform | 文件选择、下载、凭证存储、窗口行为通过适配层实现 |
| Server Core | Node.js＋TypeScript | API、存储、任务调度可脱离 Electron 独立运行 |
| Server Admin | React＋TypeScript | 复杂配置放在 Web Admin，启动器只负责启停与入口 |
| Server Launcher | Electron | 管理独立 Server 进程，不把业务逻辑写进窗口组件 |
| Worker | Python＋asyncio＋FastAPI/Uvicorn | 通信、执行器、缓存与状态分离；接收 Server 主动连接 |
| 数据库 | 首期默认 SQLite，Server 单实例 | 包含 schema 迁移；后续 PostgreSQL 另行适配，不假设自动兼容 |
| 文件存储 | 首期 Server 本地受管理目录 | 存储接口隔离；对象存储后续扩展 |
| 控制通信 | HTTPS API＋WebSocket | WS 用于事件和任务控制，不传输大媒体正文 |
| 契约 | 版本化 JSON Schema＋HTTP API 定义 | TS／Python 运行时都校验，不靠复制类型文件同步 |

具体 HTTP 框架、ORM、文本编辑器、波形库、打包工具与版本在 M0 锁定并记录 ADR；不能因此更改以上已确认边界。开发依赖采用锁文件，不在本文固定未经构建验证的最新版本号。

## 6. Studio 信息架构与连接体验

### 6.1 主要界面

1. Server 连接与首次设置。
2. 项目列表。
3. 项目画布：主画布、左侧素材入口、底部画布控制、节点上下文工具、任务状态入口。
4. 素材选择器与素材详情。
5. 任务详情抽屉。

首期提供深色、浅色、跟随系统三种选择，保存本端偏好；参考 Updream 的布局与操作层次，使用织镜自己的名称、图标和视觉资源。

已确认的视觉规则：

- 页面、侧栏、节点、菜单及普通按钮以中性黑白灰为主体，通过灰阶区分层次。
- 雾蓝只用于主要动作、当前导航、选中节点与键盘焦点；每个区域避免同时堆叠多个主按钮。
- 普通连线为灰色，选中或连接预览时强调；音频波形主体为灰色，仅播放进度使用强调色。
- 深色强调色 `#8AAAF0`，浅色强调色 `#365FB5`；分别使用深色／白色按钮文字，不用整页反色实现主题。
- 主背景深色 `#111315`、浅色 `#F5F7FA`；面板深色 `#191D21`、浅色 `#FFFFFF`。
- 成功、警告、失败保留独立状态色并配文字；原始媒体不随主题改变颜色。
- 概念图仅作为布局和氛围参考；实际实现应比概念图减少普通连线、波形及辅助控件的蓝色面积。

### 6.2 Server 连接

- 桌面版首次使用允许输入 Server 地址，也提供本机 Server 连接入口。
- Web 版默认同源连接 Server；独立部署时支持配置固定 Server 地址与允许来源。
- 显示连接中、已连接、重连中、无法连接、版本不兼容等状态，给出可执行的错误说明。
- 区分 Server 离线与 Worker 离线：Worker 离线不禁用画布编辑和素材管理。
- 首期默认单个工作空间／单管理员，采用凭证认证；不开发公开注册和多租户组织体系。
- Studio 连接远程 Server 时不得把本机 localhost 误认为远程机器的地址。

### 6.3 项目

- 项目有 ID、名称、创建／更新时间、归档状态。
- 首期每项目一张主画布；数据结构保留 canvasId，后续可增加多画布。
- 项目列表支持创建、重命名、搜索、按更新时间排序、归档与恢复。
- 项目归档保留素材和历史，默认不出现在活跃列表；归档项只读，恢复后继续编辑。
- 有非终态任务时阻止归档并提示先取消或等待；首期不提供项目永久删除。
- 无素材、无节点、无法载入等空态和错误态分别显示。

## 7. 画布与节点交互

### 7.1 画布操作

| 编号 | 操作 | 首期默认行为 |
|---|---|---|
| C01 | 创建节点 | 空白处右键选择四类节点；节点落点对应指针的画布坐标 |
| C02 | 选择 | 单击选中；点击空白清空；Shift＋单击切换多选；空白拖动框选 |
| C03 | 移动 | 拖动节点标题／非交互背景；多选时整体移动；松开形成一条撤销命令 |
| C04 | 平移 | 手形工具拖动，或按住空格临时平移；中键拖动可作辅助 |
| C05 | 缩放 | 底部按钮、百分比、滚轮／触控板；以指针或视口中心为锚点，首期默认 10%–200% |
| C06 | 适应屏幕 | 适应全部节点或当前选择，给侧栏和浮层保留空间 |
| C07 | 小地图 | 显示节点与当前视口，可点击定位，支持收起 |
| C08 | 重命名 | 标题双击或菜单进入编辑，Enter 保存，Esc 取消 |
| C09 | 调整尺寸 | 选中显示 resize 手柄；图片默认保持比例，文本和播放器遵守最小可用尺寸 |
| C10 | 分组 | 多选创建命名分组；可整体拖动、重命名、取消分组；首期无嵌套分组 |
| C11 | 查找 | 按节点标题与文本正文搜索，选择结果定位并高亮 |
| C12 | 连线展示 | 可隐藏／显示全部边，仅改变可见性，不删除关系 |

控件精确尺寸、缩放手势参数在 UI 原型中确定，必须覆盖鼠标和触控板。画布缩放不改变媒体实际分辨率或文本正文样式。

### 7.2 节点布局与独立状态

- 类型图标、标题在卡片上方；卡片内呈现正文或媒体内容。
- 选中时展示边框、连接端点和类型相关工具条；工具条定位需要处理屏幕边界。
- 空媒体节点展示上传入口；生成／模拟执行面板在选中后按需展开于节点下方。
- 节点有内容时优先展示预览和内容工具，仍可通过任务入口打开参数面板。
- 上传、播放、调进度、调音量、文本选择、编辑器内部滚动不能触发节点移动。
- 节点移动区域与素材拖出手柄明确分开。
- 内容状态 `empty/loading/ready/error`、选择状态、编辑状态和任务状态独立维护。
- 原有内容不因新任务开始或失败而消失；新结果归档后再按第 11 节规则采用。
- 第一阶段不提供节点类型原位切换，用户通过创建其他类型节点表达不同内容。

### 7.3 连线与输入角色

- 从输出端点拖出临时贝塞尔曲线；目标卡片主体可以作为吸附区。
- 候选目标高亮并显示兼容／不兼容原因。连线有独立的宽命中区域、hover 和选中样式。
- 首期普通连线表示素材／内容引用关系；建立连线不触发生成。
- 边保存 sourceNodeId、targetNodeId、sourcePort、targetRole 及顺序，不只保存视觉坐标。
- 未选择能力时，通用 reference 关系允许四类内容；同一源到同一目标同角色禁止重复。
- 选择具体操作后按能力声明校验媒体类型、数量、必需角色。多个同类型角色时要求用户分配，不能猜首帧／尾帧。
- 首期禁止自连接和引用环，循环错误在连线时提示。后续若需要视觉注释连线，作为独立关系类型设计。
- 删除边不删除内容；移动节点时边跟随；建立／删除边均可撤销。
- 上游替换内容时，下游引用状态提示变化，但不自动重新执行任务；执行时快照实际输入版本。
- 从端点拖到空白处创建节点菜单为后续增强，不阻塞首期。

### 7.4 复制、克隆、删除与撤销

| 命令 | 首期规则 |
|---|---|
| 复制／粘贴节点 | 新节点 ID；保留类型、标题、正文、资产引用、参数草稿；不复制任务执行身份 |
| 多节点复制 | 复制选择集合内部的边；不复制指向集合外部的边；分组仅在完整选中成员时复制 |
| 粘贴落点 | 有有效画布指针时以指针定位，否则放在视口中心，并偏移避免完全重叠 |
| 克隆空节点 | 保留类型、展示设置、操作选择及普通参数；清空正文、输出资产、任务关联及全部输入引用 |
| 删除节点 | 移除节点、相连边和分组成员关系；不删除素材文件，不自动取消运行任务 |
| 删除分组 | 明确区分“取消分组”和“删除组内节点”；默认操作为取消分组 |
| 撤销／重做 | 当前会话默认至少 100 条画布命令；一次拖动一条，多选操作一条 |
| 刷新项目 | 恢复已保存文档，清空会话撤销栈 |

撤销不撤销已运行的远程任务，也不删除已归档结果。文本编辑器有局部撤销栈；编辑器关闭后画布快捷键才处理画布命令。

默认快捷键：Ctrl/Cmd＋C、V、Z，Ctrl/Cmd＋Shift＋Z（兼容 Ctrl＋Y 重做），Delete／Backspace 删除选中对象，Esc 按层级关闭浮层／退出编辑／清空选择。输入框和播放器拥有焦点时优先处理自身行为。

## 8. 四类基础节点

### 8.1 文本节点

- 支持空正文、文本预览、双击编辑、保存／取消、复制纯文本、下载 UTF-8 TXT。
- 首期编辑器支持段落、H1–H3、粗体、斜体、有序／无序列表、引用、代码块及基本 Markdown 输入快捷方式。
- 富文本以版本化结构保存，并派生纯文本用于搜索、复制和作为任务输入；不直接保存不可信 HTML 执行内容。
- 卡片展示字号与正文结构分开；调整预览字号不改写文本样式。
- 正文与未来的生成提示词使用不同字段。普通文字编辑不依赖任何模型或 Worker。
- 文本入库创建内容快照。重新从库添加时建立独立正文副本，后续编辑不反向修改库条目。
- 表格、复杂嵌套格式、完整 Markdown 导入导出和文本 AI 生成为后续范围。

### 8.2 图片节点

- 支持本地上传、从当前画布／项目素材库选图、缩略预览、大图预览、替换、下载原文件。
- 首期承诺 PNG、JPEG、WebP 基础格式；不把文件名后缀等同于可解码验证。
- 预览默认等比 contain；保留原图尺寸，不因卡片 resize 修改文件。
- 加载失败显示错误与重试，不把节点误判为空；替换失败时保留原图。
- 裁剪、拼图、宫格切分按原图像素在 Studio 处理，结果另存；标注、翻转、AI 重绘、扩图、拆层后续考虑。

### 8.3 视频节点

- 支持上传／选择、封面、播放／暂停、时间进度、拖动定位、音量／静音、独立预览、替换、下载。
- 不自动播放全部节点；默认同一画布最多播放一个带声音的媒体。
- 首期兼容验收基线使用 MP4（H.264＋AAC）测试文件。MOV、WebM 等容器的可播放性取决于编码和运行平台，不承诺所有编码都支持。
- 对允许存储但当前无法解码的文件，保留原文件并提示“当前环境无法预览”，仍可下载；禁止显示虚假的播放成功状态。
- 视频截取和抽取音轨本期实现；截帧、其他高级编辑及完整时间轴后置。去字幕和片段重拍不需要。
- 后续文生、图生、首尾帧、参考重生成属于视频节点的操作模式，不增加四类以外的基础节点类型。

### 8.4 音频节点

- 支持上传／选择、波形、时长、播放／暂停、点击波形定位、播放速度、音量、替换、下载。
- 首期验收格式为 PCM WAV、MP3；M4A 等格式可按解码能力补充。
- 默认倍速菜单提供 0.75×、1×、1.25×、1.5×、2×；不要求复刻竞品的循环切换方式。
- 播放倍速只影响预览，不改写原文件或导出结果。
- 波形按需计算并缓存；大文件不能阻塞主界面，解码失败保留文件并显示说明。
- 配音正文、音色库、参考音色、情绪、语速／音高的生成控制后置。

## 9. 素材管理与生命周期

### 9.1 统一素材选择器

图片／视频／音频节点的上传或替换首先打开统一选择器，提供：

1. 本地上传：选择文件或拖入。
2. 当前画布：选择已有内容且类型匹配的节点。
3. 本项目素材：按文件夹、名称和类型查找。

跨项目素材来源在数据模型中预留，本期正式 UI 不显示空壳入口。复用素材只增加引用，不重复传输相同已存在的资产。

上传显示进度、取消、失败重试与大小限制。首期默认单文件上限 1 GiB，可由管理员修改；不承诺分块断点续传，失败后完整重传应明确说明。

### 9.2 项目素材库

- 在画布侧栏打开；支持网格／列表、名称搜索、类型筛选、名称／创建时间排序。
- 支持创建／重命名／移动文件夹和条目、子文件夹、面包屑导航；移动文件夹不得形成循环。
- 默认只有项目素材根目录，不强制创建角色、场景、分镜等专业分类。
- 素材详情包括名称、描述、类型、大小、创建时间，以及可用的尺寸／时长。
- 支持多选与批量“添加到画布”“移出素材库”；批量文件下载打包后置。
- 显示资源加载、上传中、归档失败、内容缺失等不同状态。

### 9.3 双向复用和命名

| 路径 | 行为 |
|---|---|
| 素材库 → 添加到画布 | 新建对应类型节点，保留素材条目；媒体复用资产引用，文本复制正文快照 |
| 节点 → 复制到素材库 | 新建 LibraryItem，原节点保留；支持四类内容和多选 |
| 节点素材手柄 → 素材库 | 与菜单入库同语义；不得把节点从画布移除 |
| 素材库拖入画布 | 在落点创建节点；与节点移动手势区分 |
| 当前画布内容 → 替换节点 | 复用当时的资产版本，不创建隐藏的持续同步关系 |

- 节点标题与素材名称独立，修改一方不自动重命名另一方。
- 同文件夹同名入库使用“名称 (2)”等后缀，不静默覆盖。
- 首期复制和拖拽仅保证当前 Server／项目内使用；跨 Server 剪贴板迁移后置。

### 9.4 资产与删除规则

- Asset 为不可变内容记录；替换内容生成或引用新的 Asset，不覆盖旧字节。
- 上传到节点会持久化资产，但不自动创建已整理的 LibraryItem；因此素材库与画布内容不必一一对应。
- 替换 LibraryItem 指向新资产，不自动替换已引用旧资产的节点；用户需要在节点明确替换。
- 删除节点仅删除画布引用。移出素材库仅删除库条目。运行任务输入、结果历史及其他节点引用仍有效。
- 删除非空文件夹需明确确认，移除其组织条目，但不物理删除被引用的资产。
- 首期不提供用户可触发的资产永久清除或自动清除孤立原文件；管理员看到磁盘占用，后续再加入基于引用与保留期的回收机制。
- 未完成上传、任务临时文件可以按配置清理；Worker 只有在 Server 确认归档后才能清理结果临时文件。
- 原始素材、缩略图／波形派生物、Worker 临时输入分别存储。派生物可重建，原始资产不可依赖 Worker 存活。

## 10. 保存、恢复与数据模型

### 10.1 自动保存与冲突

- 首期默认编辑停止约 1 秒后自动保存；连续交互期间最长约 5 秒形成一次持久化批次。
- UI 显示“保存中／已保存／未保存／保存失败”，不能在仅写入客户端状态时显示已保存。
- 画布文档有 revision。写入携带 baseRevision，Server 原子检查；冲突返回 409，不覆盖其他客户端更改。
- 本期不做多人合并。冲突时保留本地草稿，允许导出副本或刷新远端版本，由用户选择。
- 断线后保留本地恢复草稿，禁止提交新任务；不能用重新连接后强制覆盖远端来解决冲突。
- 重开项目如存在恢复草稿，比较 revision 后提示恢复；本期不承诺断网期间完整素材操作和跨端离线同步。
- 浏览器关闭前提示受平台限制，不能仅依赖关闭事件实现保存。桌面版关闭时将未保存修改同步写入本机草稿后退出，重开项目时提供恢复；仍在上传或草稿写入失败时显示明确的继续编辑／仍然关闭对话框，不得静默拦截关闭。
- 视口位置／缩放按用户和客户端保存，与内容 revision 分离，避免两个窗口仅移动视口就冲突。

### 10.2 核心实体

| 实体 | 关键字段与职责 |
|---|---|
| Project | id、name、archivedAt、createdAt、updatedAt |
| CanvasDocument | id、projectId、schemaVersion、revision、nodes、edges、groups |
| CanvasNode | id、type、title、position、size、textDocument 或 currentAssetId、generationDraft、resultHistory |
| CanvasEdge | id、sourceNodeId、sourcePort、targetNodeId、targetRole、order |
| NodeGroup | id、title、memberNodeIds、bounds；成员首期最多属于一个组 |
| GenerationDraft | operation、capabilityId、parameters、inputBindings；与已提交 Job 分开 |
| Asset | id、kind、mimeType、size、sha256、storageKey、metadata、createdAt、provenance |
| LibraryItem | id、scope、projectId、folderId、name、description、assetId |
| Folder | id、scope、projectId、parentId、name |
| Job | id、projectId、canvasId、nodeId、requestId、inputSnapshot、parameters、status、currentAttemptId、outputs |
| JobAttempt | id、jobId、workerId、leaseId、status、progress、error、timestamps |
| Worker | id、name、credentialRef、connectionState、lastHeartbeat、capacity、capabilitySnapshot |
| Capability | id、version、operation、inputSchema、parameterSchema、outputSchema、availability、simulation |

- ID 全局唯一，时间使用 UTC，界面按本地时区显示。
- 正文结构与画布文档都必须包含 schemaVersion，并有迁移策略；打开更高不兼容版本时拒绝写入。
- 媒体节点持久化 Asset ID，不保存临时 object URL、本地绝对路径或带时效的下载 URL。
- Job 输入包含文本快照或资产 ID＋hash，不在执行中读取不断变化的节点当前值。
- provenance 可记录源任务、输入资产和处理方式；本期不做复杂溯源图 UI。

## 11. 模拟执行与任务体验

### 11.1 模拟能力

模拟的只有计算，认证、调度、输入下载、文件校验、结果上传、归档和 UI 更新必须走真实链路。

| 能力 ID 草案 | 输入 | 执行与输出 |
|---|---|---|
| `mock.text.echo.v1` | 文本快照 | 延迟后生成带模拟标记的文本结果 |
| `mock.media.copy.v1` | 一个图片／视频／音频资产 | 下载到任务目录，校验并复制输出，再通过结果接口上传 |

- 模拟能力始终标记 simulation=true，界面显示“模拟执行”，不能用真实模型名称或宣称生成成功。
- 媒体模拟须覆盖图片、视频、音频三类；复制文件也必须经历输入下载和产物上传，不能只把输入 Asset ID 当结果回传跳过链路。
- 测试配置支持延迟、明确失败、暂停后取消等可控场景；故障注入只在开发／测试模式可见。
- 正常画布不铺满未接入的 AI 工具按钮。用户展开执行面板后才能选择可用模拟能力。
- 暂不安装 PyTorch、ComfyUI、模型权重或 GPU 驱动作为模拟 Worker 的运行前置条件。

### 11.2 用户提交与结果采用

1. Studio 校验必需输入并提交 requestId、操作、参数、输入引用及源节点 revision。
2. Server 再次校验权限与能力，固定输入快照并持久化 Job，然后返回 jobId。
3. Worker 不在线时任务保持排队，提示“等待可用 Worker”，画布继续可用。
4. 运行时显示阶段、可测进度及取消入口；未知百分比使用不确定进度，不编造 ETA。
5. 结果在 Server 完成文件与清单校验、持久化后才算任务成功。
6. 若节点仍存在且从提交后未更换输入／内容、该任务仍是节点的最新提交，默认自动采用输出。
7. 若节点已修改、已删除或已有更晚提交，结果仅进入任务记录／节点结果历史，提示可手动采用，不覆盖当前内容。
8. 首期每个节点最多一个非终态任务；不同节点可独立排队。未来多候选批量生成另行扩展。

复制节点不复制运行中的 Job。删除节点不取消 Job，任务详情可继续查看和取消。任务结果始终可以从任务详情添加回画布或素材库。

### 11.3 状态与恢复语义

| 状态 | 含义 | 允许的主要后续状态 |
|---|---|---|
| queued | 已持久化，等待调度 | assigned、cancelled |
| assigned | 已分配尝试与租约，等待 Worker 确认／开始 | running、cancel_requested、interrupted |
| running | 执行中，含输入准备、处理、结果上传阶段 | succeeded、failed、cancel_requested、interrupted |
| cancel_requested | 已记录取消请求，等待实际停止确认 | cancelled、interrupted |
| succeeded | 结果已归档并提交 | 终态 |
| failed | 有明确执行错误 | 终态；用户可创建重试尝试 |
| cancelled | 排队任务取消或 Worker 已确认停止 | 终态 |
| interrupted | 失联／重启后无法确认执行结果 | 终态；用户可创建重试尝试 |

- cancel_requested 不能仅因点击按钮立即显示 cancelled。
- Server 对取消与完成使用原子状态转换：如果成功已提交则取消返回已结束；如果取消请求先提交，迟到结果不成为正式成功输出。
- requestId 是提交幂等键：同键同负载返回原 Job，同键不同负载返回冲突。网络重试沿用键；新创作使用新键。
- 手动重试 failed／interrupted Job 创建新的 attemptId，保留原输入快照和旧尝试记录；修改参数后需创建新 Job。
- 重试按钮仅在旧尝试已失效并完成必要终止检查后可用，不承诺恰好执行一次。
- 心跳超时只说明失联；需要结合租约判断任务，不立即把所有任务重发给别的机器。
- 已分配或运行中的尝试超时且状态不明时进入 interrupted，默认不自动启动可能重复消耗算力的执行。
- Server 重启后从数据库恢复排队任务，与重连 Worker 核对运行尝试；完成终态不可被重连消息回退。
- Worker 重启后报告本地恢复日志。模拟任务可以中断后重试；真实推理是否恢复由未来适配器声明，不许统一宣称可续算。

## 12. Worker 运行要求与协议草案

### 12.1 Worker 程序结构

```text
Worker CLI
├─ 配置与凭证
├─ FastAPI/Uvicorn HTTP 与 WebSocket 接入
├─ asyncio 心跳与任务运行
├─ 本地任务／租约记录
├─ 输入接收缓存与结果下载服务
└─ Executor 接口
   ├─ MockExecutor                 已实现
   ├─ ComfyUIExecutor              协议已实现，上海二 A 5090 图片样本已验收
   ├─ PythonProcessExecutor        后续
   └─ MediaToolExecutor            CPU 截取和抽音轨已实现
```

- 核心模块不依赖 FastAPI 的 Request、路由或生命周期对象。
- HTTP/WebSocket 适配层调用执行核心，提供鉴权、身份检查、控制消息和文件传输；由 Server 负责重连。
- CPU 密集或阻塞任务、模型推理放入受管理的独立进程／引擎，避免阻塞 asyncio 心跳循环。
- 默认同时执行一个任务，可声明 capacity；首期通过两个模拟 Worker 验证多执行端调度。
- 每次 attempt 使用隔离目录，禁止多个任务共享会被单方清理的临时输入路径。
- 取消需要停止对应任务及其受管理子进程；不杀其他任务或无关 ComfyUI 运行项。
- 收到停止接收新任务指令后进入 draining，当前任务可继续；明确停止进程时给出任务将中断的提示。

### 12.2 接入与心跳

1. Worker 启动受鉴权保护的接入服务，生成独立 workerId 和接入密钥，默认监听本机 4320。
2. 管理员在 Server 填写 Worker 地址和密钥；测试连接核对身份、协议与绑定状态，再保存。
3. Server 主动建立受认证 WebSocket；Worker 发送能力及本地活动尝试摘要，双方确认后接单。
4. 每个 Worker 状态目录绑定一个 Server 身份；不同 Server 使用独立 Worker 状态目录。网络断开时不解除绑定。
5. Worker 定时报告心跳；Server 负责指数退避重连。Server 的入站地址不出现在任务或 Worker 配置中。

默认参数用于首期测试，可配置：心跳每 10 秒一次，40 秒无心跳显示离线，任务租约默认 90 秒并续期。Worker 丢失租约后不得开始新计算；在安全点停止旧尝试并保留诊断信息。Server 仅接受有效当前 attempt／lease 的结果提交。

Worker connectionState 与任务状态分开：connected、disconnected、draining、disabled。disabled 的 Worker 不再获得任务，Server 停止其连接并不再派发新任务，已有任务遵循取消和租约语义。

### 12.3 能力声明

能力声明至少包含：

- capabilityId、version、operation、displayName、simulation。
- 输入角色、允许类型、最少／最多数量，参数 Schema，输出类型。
- 实现版本、可用状态与不可用原因；capacity 等调度信息。
- 状态区分 installed、ready、busy、unavailable；“发现模型目录”不等于 ready，更不等于真实推理已验收。

Studio 从 Server 获取聚合目录；不直接依赖某个 Worker 的 ComfyUI 节点名称。能力变更时重新校验草稿，已提交任务仍使用固定能力版本与快照。

### 12.4 消息信封与顺序

控制消息统一包含：

```json
{
  "protocolVersion": "2.0",
  "messageId": "unique-id",
  "type": "task.progress",
  "timestamp": "2026-09-25T00:00:00Z",
  "workerId": "worker-id",
  "jobId": "job-id",
  "attemptId": "attempt-id",
  "leaseId": "lease-id",
  "sequence": 12,
  "payload": {}
}
```

非任务消息可省略 job／attempt／lease 字段，必填条件由每种消息 Schema 定义。

| 方向 | 消息类别草案 |
|---|---|
| Worker → Server | hello、heartbeat、capabilities、task.accepted、task.progress、task.failed、task.cancelled、task.result_ready、reconcile |
| Server → Worker | welcome、task.assign、task.cancel、task.commit_ack、lease.renewed、drain、error |

- 控制消息允许重复投递，接收方按 messageId 与 attempt 状态去重。
- 进度按 attempt 内 sequence 合并，拒绝旧序号回退；重连先查询状态再继续发送。
- WS 不是持久化日志的替代品，断线后能通过 HTTP 查询权威状态。
- 版本 major 不兼容时拒绝连接；minor 新增字段按契约兼容规则处理。核心请求拒绝未知字段，扩展元数据使用显式 extension 容器。
- 不通过协议传输云平台主账号密钥、模型绝对路径或任意 Shell 命令。

### 12.5 文件传输与结果提交

- 控制通道传递 Asset ID、hash、大小与受限传输授权；文件走 HTTP 流式接口。
- Worker 仅可访问其当前尝试需要的输入，以及上传该尝试的输出；不能枚举所有项目文件。
- 输入下载完成后校验大小与 SHA-256，再交给执行器。
- 输出上传进入暂存区，Server 校验并完成原子归档。结果清单引用 Server 确认的上传 ID，不接受任意本机路径。
- result_ready 携带输出清单；Server 幂等提交 Job 结果并发送 commit_ack。
- commit_ack 丢失时 Worker 查询任务并重试提交，不能重复创建正式结果记录。
- 无效旧租约、已取消任务的迟到上传不能覆盖新尝试；暂存产物按保留策略清理。
- Worker 收到归档确认后可清理本次目录，清理失败只产生可处理告警，不把已成功任务回退。

## 13. Server API 与管理后台

### 13.1 API 草案

路径为开发基线，M0 通过契约测试固定。所有写接口与私有读取必须认证，错误统一为 code、message、details、requestId。

| 资源 | 主要接口草案 | 核心约束 |
|---|---|---|
| 系统／会话 | `GET /api/v1/system`、会话建立／退出 | 返回 API／协议版本与可用状态，隐藏敏感配置 |
| 项目 | `GET/POST /api/v1/projects`、`PATCH /projects/{id}` | 重命名、归档恢复；首期不永久删除 |
| 画布 | `GET/PUT /api/v1/projects/{id}/canvas` | schemaVersion、baseRevision；409 保存冲突 |
| 资产 | `POST /api/v1/assets/uploads`、上传完成确认、`GET /assets/{id}` | 元数据与文件分离，类型／大小／hash 校验 |
| 媒体访问 | `GET /api/v1/assets/{id}/content` 或受限访问 URL | 支持视频／音频 Range，授权与失效时间明确 |
| 素材库 | `/api/v1/projects/{id}/library/items`、`/folders` | CRUD、搜索筛选、批量添加、移出而非物理删文件 |
| 能力 | `GET /api/v1/capabilities` | 与可执行状态分开呈现；模拟标记不可丢失 |
| 任务 | `POST/GET /api/v1/jobs`、`GET /jobs/{id}` | 幂等键、固定输入、分页记录 |
| 任务控制 | `POST /jobs/{id}/cancel`、`POST /jobs/{id}/retry` | 状态原子转换，重试产生新 attempt |
| Worker 管理 | `/api/v1/workers`、接入凭证创建／撤销 | 权限独立于普通素材操作 |
| 实时事件 | Studio 事件 WS、Worker 控制 WS | 身份与消息类型隔离 |

媒体 `<video>`／`<audio>` 不应依赖浏览器无法添加的自定义请求头。默认同源 Web 采用受认证会话；跨源／桌面媒体使用短期且限定资产的访问授权。不得把长期管理员或 Worker token 放入媒体 URL，持久化文档也不得保存临时 URL。

Studio 重连后刷新项目 revision、非终态任务和 Worker 状态快照，再续收事件；事件只作为及时更新机制，不是恢复唯一依据。

### 13.2 Web Admin

首期导航限定：

| 页面 | 内容 |
|---|---|
| 概览 | Server 状态、版本、数据目录、磁盘占用、在线 Worker、任务计数 |
| Workers | 接入凭证、在线／忙闲、能力、最近心跳、禁用／撤销、drain |
| Jobs | 筛选、输入／输出、阶段、错误、attempt 历史、取消与重试 |
| Storage | 数据目录和容量、上传限制、资产／暂存占用、备份说明 |
| Settings | 监听地址、端口、允许来源、认证、基本保留策略 |

首期无 Provider 计费配置、云平台自动开关机、用户组织、Agent 管理等空页面。日志应能按 jobId／attemptId／workerId 定位，默认不记录完整提示词、素材正文或秘密凭证。

- 首期发布 Python 包／锁定依赖与 CLI，可在本机 Windows 和 Linux 运行模拟任务。

## 15. 非功能要求

### 15.1 可用性与性能目标

以下为首期工程验收目标，不是当前已达到的性能声明。测试需记录机器、浏览器、分辨率与媒体规格。

- 基准场景：100 个混合节点、150 条边，包含媒体缩略图；打开项目后平移／选择应保持可操作，基准环境平均交互帧率目标不低于 30 fps。
- 原图和视频按需加载，画布不同时解码／播放全部媒体；不把原文件或 Base64 写进画布 JSON。
- 100 节点基准画布文档在本地 Server 的初次读取和基础渲染目标 3 秒内，不含大媒体下载。
- 流式上传下载不能把完整大文件装入 Server／Worker 内存；界面提供进度与取消反馈。
- 超出已测规模时允许性能下降，但不得因节点离屏丢失数据；更大规模优化另列里程碑。

### 15.2 安全与数据完整性

- 所有外部参数、上传名、媒体类型、尺寸、路径和契约都做边界校验，原始文件名不直接决定服务端文件路径。
- 富文本不执行脚本；Electron 渲染层不直接获得任意文件系统或进程执行权限。
- 远程连接使用 TLS；本机回环开发可使用 HTTP。
- 文件上传采用暂存＋确认，任务结果采用幂等提交；磁盘满、校验失败、上传中断都有具体错误。
- 首期单管理员仍需区分 Studio 会话与 Worker 凭证，不因个人使用而默认开放无鉴权公网接口。
- 本地缓存清理不删除 Server 唯一原件，Worker 卸载不影响已归档项目。

### 15.3 可诊断性

- 请求与任务携带关联 ID；错误分为连接、认证、版本、输入、资源、执行、上传和归档阶段。
- 管理员能判断“Worker 在线但没有能力”“能力已安装但未就绪”“正在忙”“结果尚未归档”。
- UI 不将模型目录可见、HTTP 健康或测试通过等同于真实推理验收。

| A09 | 媒体与错误 | PNG、JPEG、WebP、基准 MP4、WAV、MP3 正常；不支持编码和坏文件有明确反馈 |
| A10 | 素材双向复用 | 节点入库后保留，库添加画布后保留；同名不覆盖；文本为快照，媒体为不可变资产引用 |
| A11 | 删除与替换 | 删除节点／移出库不破坏其他引用；替换失败保留原内容；旧资产仍可供旧任务访问 |
| A12 | 模拟完整链路 | 文本和三类媒体各完成一次；结果经下载／上传／归档，hash 与结果清单一致，始终标明模拟 |
| A13 | 两 Worker 调度 | 一个任务只分配给当前有效尝试，按能力／容量调度；断线不盲目重复运行 |
| A14 | 幂等与消息重复 | 同请求键不建重复 Job；不同负载冲突；重复进度／结果消息不回退状态或产生重复记录 |

| A16 | 输入快照 | 提交后修改节点，执行仍用原输入；完成结果不覆盖后来修改或更晚任务 |
| A17 | 重启与失联 | Server／Worker 分别重启有可解释恢复结果；未知任务进入 interrupted，不假报成功／续算 |
| A18 | 临时目录隔离 | 两任务引用同一资产时，清理一方不影响另一方；云 Worker 删除后正式结果仍可访问 |

| A20 | 双形态 | Web／桌面同项目一致；Studio 退出不关闭 Server；Windows 两安装包无需全局 Node/Python |
| A21 | 远程模拟 | Server 主动连接 Linux Worker；断网重连、文件传输和租约核对通过，不要求 Server 公网入站 |

## 24. 0.2.2 连线与应用辨识修订（2026-09-25）

### 24.1 Studio 0.2.3 外侧连接点与动效

- “＋”圆圈 18px、内部图形 11px；最终位置完全处于节点外侧，与内容边缘留约 4px 空隙。
- 悬停时从边缘向外位移，同时由 20% 缩放渐长至 100% 并渐显，时长 220ms，采用平滑减速曲线；移出反向收起，不旋转、不弹跳。尊重系统减少动态效果偏好。
- 32px 透明命中区域保持固定并覆盖节点到外侧圆圈的间隙，移入圆圈不能闪烁或消失；连线锚点始终固定在节点边缘。

### 24.2 Studio 0.2.4 连线手势

- 从输出连接点拖到另一张媒体卡片内部任意位置即可连接，无需精确命中输入小圆圈；从输入连接点反向拖到来源卡片同样成立。分组本身不是连接对象。
- 拖动中的曲线跟随指针；有效目标高亮，预览吸附到对应边缘。重复或循环引用显示无效反馈且不提交。松开后恢复普通连线，撤销/重做仅操作关系。
- Esc 取消当前拖拽，即使随后在目标处松开也不创建连接；空白处释放取消。保留端口之间的点选连接作为补充。
- 竞品实测：Updream 音频输出拖到视频卡片内部会建立连接；点击输出“＋”或从视频输出拖到空白处会创建 Agent。仅采用卡片接收连线行为；Agent 继续排除在本期范围外。目标高亮、取消和无效颜色为本项目方案，不宣称逐帧复刻竞品。

### 24.3 Studio 0.2.5 连接过程的视觉状态

- 悬停且未连接时，外侧“＋”沿用向外渐长动效；正在连接时统一隐藏各节点的圆圈及加号，保留指针命中区域，不改变锚点位置。
- 自由拖动时曲线从节点边缘出发，线尾用半径 2.5px 的同色实心点跟随指针。吸附有效目标（卡片或端口）后隐藏线尾点，曲线直接到达目标边缘，仅保留轻度高亮。
- 连接完成、空白处释放或 Esc 取消后退出连接状态，根据指针位置恢复悬停动效；不得残留加号、预览点或目标高亮。

## 25. Studio 0.3.0 首批创作工具

- 系统剪贴板包含图片或文件时走现有上传流程；包含普通文字时创建文本节点，保留换行。外部 HTML 不作为画布代码执行。超过 12,000 字整段拒绝并提示分段，不静默截断。
- 外部粘贴有有效画布指针时使用指针位置，否则使用视口中心避让；同一窗口的节点复制沿用已有偏移布局和内部连线复制。节点快照通过当前剪贴板标记识别，外部新内容替换剪贴板后必须优先粘贴新内容。跨窗口富节点剪贴板暂不承诺，文字仍可作为普通文本粘贴。

- 文本工具提供正文/标题 1–3、粗体、斜体、下划线、删除线、无序/有序列表、引用、代码块、清除格式和局部撤销/重做。工具状态随选择变化；实时显示字数，超限禁用保存。格式保存后重新进入编辑器应还原；画布卡片继续显示纯文本摘要。
- 素材库与替换选择器支持视频静态缩略图、音视频时长；素材库及详情展示格式、文件大小、图片/视频尺寸和音视频时长。读取失败显示真实错误并允许重试，不填造数据。
- 首批采用客户端按需解码：预览接近可视区域后读取，最多两份同时处理；按 Server 与素材哈希去重，最多缓存 200 条预览信息。视频取靠近开头的静态帧，最长边不超过 320px。任务结束释放临时媒体解码资源；缓存不可用不影响素材使用。
- 缩略图缓存属于本机浏览器/Electron 用户目录，不替代 Server 正式资产或服务端检索索引；换设备后按需重建。服务端元信息索引、回收站、原文件清理、完整混合媒体性能基准、远程 Worker 和安装升级仍列后续工作。

## 26. Studio 0.3.1 媒体节点比例与紧凑控制（2026-09-26）

- 有图片/视频内容的节点按素材原始宽高比贴合，不由固定最小高度或播放器底栏撑出空白；不裁剪和拉伸素材。读取到尺寸后自动适配旧节点，保留节点 ID、位置与连线。
- 节点角点缩放保持宽高比，更新后的尺寸保存并在重开后恢复。更换素材后根据新素材比例重新计算高度；旧素材延迟上报的尺寸不能覆盖新引用。节点保存的尺寸信息带素材 ID。
- 视频圆形播放按钮固定在画面中心，悬停或选中不改变位置、大小。底部播放、时间、进度、倍速、音量、全屏整合为单行浮层；不占用媒体之外的空间，悬停/键盘聚焦时显示。节点内仅显示已播放时间，详情/全屏保留总时长。
- 替换入口保持内部下方居中，视频底部间距 36px、高 24px；与中央播放圆圈、时间轴独立。视频最小高度 160px，超宽视频必要时按比例扩宽，保证控件不叠压，不能通过拉伸内容留出空间。
- 音频默认高度从 132px 缩至 108px，旧节点加载时同步收紧；保留 64px 波形及播放/定位/音量/倍速，主要减少波形下方到控制栏的留白。

## 28. 图片执行链路（Studio 0.5.0 / Server 0.4.0 / Worker 0.3.0）

- 操作先于模型：文生图、图片指令编辑、多图参考。单击空图片节点直接展开编辑区，文本/已有图片节点保留工具栏生成入口；初始提示词和有序参考来自当前节点及上游，用户可修改和重排。
- 模型切换保留提示词、参考图和参数，不支持时明确禁用提交。生成草稿与待重试请求随项目保存，重新打开恢复；保存失败保留本机草稿。
- 2512 文生图使用独立 qwen2512-v1；2.1 使用 qwen21-v1。2512 不接受参考图；编辑 1 张，多参考至少 2 张、至配置上限。输入单张不超过 64 MB，来源资产不可变。
- 文生图宽高均为 32 倍数，范围由 Worker 配置声明；参考编辑不接受手填宽高，以第一张图比例和 referenceResolution 构建潜空间。RGBA 只保留模型实际输出通道，不能通过给 RGB 添空通道宣称完成透明生成。
- Worker Python 3.11+，asyncio + FastAPI/Uvicorn 接入服务，httpx 只用于内部引擎请求，ComfyUI 为专用本机引擎。默认不启用图片能力；必须用 --enable-image-execution 和专用配置显式开启。
- Worker 用加载器文件列表确认模型名称、用 object_info 确认节点存在；文件名和图结构只由 Worker 控制。多个 Worker 的 profile 指纹一致才可承接相同任务，不能仅凭“支持图片”调度。
- ComfyUI 任务 UUID 对应执行尝试；提交前落本地记录。取消仅针对该 UUID，响应丢失不重发 prompt；无法确认停止则撤下图片能力。重启先核对遗留提交，不自动重新生成。
- 输入校验/下载、图片执行、输出校验/归档显示实际阶段。没有采样进度时为不定进度，禁止编造百分比；心跳不被阻塞。
- 输出新建 Asset 和画布节点，归档记录有序参考、模型/配置/工作流、种子和参数。Server 根据 Job 写来源，不接受客户端伪造执行结果归属。
- 本轮边界：本机测试服务、真实 Python Worker 与浏览器交互验证；并非真实 Qwen 出图验收。GPU 阶段需验证 2512 文生图、2.1 文生图/编辑/多参考/RGBA、取消、显存与耗时，运行前告知用户。

- 单击空图片节点展开图片生成与编辑；空文本节点展开本地文字编辑；空视频、音频节点展开素材入口，明确生成尚未接入。已有文本/图片节点仍可从工具栏进入图片生成。

- 收起再打开后重试失败的图片请求，继续使用相同请求 ID 和随机种子；成功后清除该次请求，允许用户再生成。结果继续新建节点，保留原始内容。
- 视频画面、音频波形本体允许从首次按下就拖动节点。视频只由播放按钮切换播放；画布音频单击波形定位、按住移动拖节点，详情预览中的波形保留拖动定位。播放按钮、视频进度、音量、倍速与替换入口独立，不参与节点拖动。

## 31. Server 主动连接 Worker（协议 2.0）

- 管理台仅填写执行端名称、Worker 地址和密钥；提供测试、保存、连接设置、停用和排空。地址必须从 Server 所在机器可达。
- Worker 提供鉴权 GET /api/v1/system、WS /api/v1/connect、PUT /api/v1/attempts/:attemptId/inputs/:assetId、GET /api/v1/attempts/:attemptId/output。大文件使用流式 HTTP，不塞进控制消息。
- assign → accepted → Server 上传输入 → inputs_ready → 执行/进度 → result_ready → Server 下载并校验归档 → commit_ack。无输入任务直接执行。
- 文件访问限定当前 attempt/lease，输入按声明大小/SHA-256 校验后原子落盘；输出按实际字节与声明校验，归档确认前 Worker 保留输出。同一连接断开重连不重新提交生成。
- Server 保留私有身份和连接密钥文件，列表不返回密钥；Worker 独立状态目录保留身份、绑定与执行临时文件。协议 1.0 注册/回调接口移除，不维护初版历史兼容层。
- 网络可达性由用户自行解决。不内置 SSH、组网、中继，不提供 TunnelFlow 示例、链接或配套入口。
- 首期文件中断可重新传输完整文件、已完整上传的输入去重；暂不宣称分块断点续传。真实平台 HTTPS/WSS 与模型推理已在上海二 A 按第 32 节验证。

## 37. 统一模型、任务调度与 Worker 管理（0.13 / 0.10 / 0.9）

- 独立文本生成和主动提示词优化接入 Server 管理的互联网语言模型；纯文本、图片理解、结构化输出分别声明。Qwen 编码器、IndexTTS 情绪模型不作为通用语言模型。优化失败保留原稿，应用建议才替换，不强制优化、不引入积分。
- 模型执行规格采用可移植 SHA-256 身份，明确权重修订、量化、工作流、输入输出限制；本机路径与部署配置分离。相同规格聚合多个 Worker，默认自动选择，高级选项固定 Worker；不自动换模型。
- Server 分离 GPU、互联网 API 和 FFmpeg 队列；Worker 容量 1，多 Worker 并行，同物理 GPU 共用资源锁。队列跳过暂不可执行任务，明确排队、离线、上游等待、取消中与失败原因。结果归档后仍需确认 GPU 释放；崩溃/释放失败持久隔离。
- 批量独立提交与显式流程分开。普通连线引用已有素材；运行流程才按显式绑定等待新结果，检查循环及输入类型。提交冻结参数、规格、素材版本和规则版本；上游失败仅影响相关后代。保留幂等、取消、手动重试。
- Worker 核心按需加载独立 image/speech/video 适配器，复用已有 ComfyUI/IndexTTS 环境；安装路径、设备、工作目录和模型由部署配置提供。公共模型链接属于平台部署流程，不写进业务调度。
- Worker 增加 React/TypeScript 静态管理页，由一个 FastAPI/Uvicorn 进程提供。概览、执行器、环境、接入、诊断五页；缺依赖仍能进入管理页。CLI 与页面共用配置和管理逻辑，运行中的服务唯一拥有状态目录。
- 部署管理凭证与 Server 接入凭证分离，API 逐请求鉴权。支持无 Server 连接时配置和诊断；执行器工作不阻塞管理接口。系统服务/容器负责 Worker 启停与异常重启。
- 先配置已有环境并检查、启停、诊断，再使用显式标准安装。程序、身份、配置、推理环境、模型、任务缓存、日志分开；升级保留身份，镜像不含运行数据。安装、模型检查、服务启动、模型下载、真实 GPU 测试互不自动触发。
- 支持目标优先 Linux/WSL2；Windows 原生推理另行验收。基础媒体执行位置不变；不做自动扩容、复杂显存预测、抢占、云购买、SSH/组网/中继。

完整字段、状态、界面及限制见 `zhilume-server/docs/model-and-scheduling.md`；Worker 部署见 `zhilume-worker/deploy/management.md`。本轮验收与未验证项见 Server `docs/model-scheduling-acceptance-2026-09-27.md`。

## 38. Worker 已有环境配置体验

- 引擎名称统一为“Qwen 图片”“H3 视频”“IndexTTS 语音”，界面仍以执行器页管理启停。Qwen/H3 标注 ComfyUI 服务，IndexTTS 标注独立 Python 进程；模型、推理程序和适配器不混为同一概念。
- 环境页默认结构化表单，按引擎保留未保存草稿，JSON 作为高级编辑入口，两种视图使用同一配置对象。保存与检查、启用分开；更换配置后清除旧检查结论。
- Qwen/H3 配置已有专用 ComfyUI URL、独占确认、超时、释放上限和多模型执行规格。Python、ComfyUI 程序/模型目录、GPU 设备由外部 ComfyUI 服务启动配置决定，不提供不生效的本机字段。两种适配器可以指向同一专用服务。
- IndexTTS 配置独立 Python、程序目录、模型目录、工作目录、FFmpeg、设备及能力限制。空工作目录使用程序目录。所有路径指 Worker 部署机器，非浏览器机器。
- 模型表单包含组件文件、权重版本、量化、固定组件标识及输入输出限制；模板不伪造模型身份，不自动下载。原有不可变规格匹配规则保持不变。
- 只读检查逐项显示 checking/passed/failed/skipped、原因及处理建议：服务可达性、路径/软链接、基础 Python 依赖、规格、GPU、模型文件与工作流。缺 GPU 不阻止其余检查；检查不加载模型、不执行推理、不下载依赖。
- 部署操作显示开始/结束时间、进行中/完成/失败与具体检查阶段，不编造耗时百分比；每个引擎可读取最近 60 条脱敏部署事件。安装/检查/启停日志不冒充原始推理控制台日志。
- 管理接口继续独立鉴权。新增模板与日志端点同样拒绝任务接入凭证。日志写入排除后台 task 对象，重启后可读；环境错误不破坏管理服务。


## 39. Worker 通用部署与托管运行环境（0.10）

- 先完善跨机器部署基础，再接入通用语言模型。当前已实现 llama.cpp 语言执行器接入与控制基础（真实 GPU 待验收），Qwen3.5-9B 是后续首验候选，不把 Qwen Image 编码器视为语言服务。
- Linux/WSL2 核心发布包包含 wheel、安装入口与模板，不需要克隆整个开发仓库或在部署机器安装 Node.js。安装、初始化、版本激活、回退和服务启动分别执行；程序与 state 不允许嵌套。切换版本持有 state 独占锁，运行中拒绝切换，不覆盖身份和数据。
- core、独立推理环境、模型和用户状态保持分离。发布包采用明确文件清单，只包含程序、静态页面、协议和无凭证模板。安装记录 wheel SHA-256 与实际依赖清单；未声称已有完整 CUDA 依赖锁。
- 图片/H3 可选复用外部专用 ComfyUI 或 Worker 托管本机 ComfyUI。运行环境 id、Python、程序目录、模型路径 YAML、GPU 序号和端口是部署配置，不进入模型执行规格。两种执行器可共用一个 runtimeId；IndexTTS 继续受管独立任务进程。
- 管理页分别提供保存服务配置、检查程序路径、启动服务、等待任务后停止和取消任务后停止。服务在线、执行器接单、真实推理验证分别显示。CLI 调用同一管理 API，任务接入凭证不得配置或控制运行环境。
- 停止共享服务前先停止所有关联执行器接单，再等待/取消任务并核对资源释放。未知端口进程不接管；正常关闭回收自建进程组，异常重启由系统服务/容器回收。GPU 释放未确认的隔离标记不因进程退出而清除；仅允许原环境重新启动以恢复。
- 托管服务默认不随 Worker 重启自动启动；用户重新显式启动和启用。不复制旧任务或推理状态，不隐式加载权重。此启动策略在管理页明确说明。
- 通用 Linux 模型搜索目录与云平台公共软链接分开配置。容器核心模板持久化 state、共享宿主机 GPU 锁目录；GPU 环境另行准备，模板不能冒充已验收的推理镜像。
- 验收分层：Windows 管理/协议回归、WSL2 实际进程与发布升级验收、目标机器真实 GPU 验收。其他云平台、自有 Linux GPU、容器 GPU 及新托管模式完整 ComfyUI/IndexTTS 依赖安装未验收；普通媒体处理位置保持不变。

- 2026-09-27 上海二 A 托管模式实测通过：Qwen/IndexTTS/H3 切换并归档，取消视频后停止共享 ComfyUI、释放显存，再启动生成成功；正常重启回收进程并保留身份/凭证/绑定。Server 无入站监听。完整证据见 Server docs/worker-managed-gpu-acceptance-2026-09-27.md。复用环境验收不代表全新安装、其他平台、硬崩溃或多卡验收。

## 40. Worker 标准安装流程（0.11）

- 核心与推理 Python 分开：核心建议 3.12，ComfyUI 标准方案使用 3.12，IndexTTS 使用 3.11。Qwen/H3 共用一个 ComfyUI，语音独立环境。
- 新目录安装，下载前检查平台、基础工具、解释器版本和最低磁盘余量。程序、环境、包缓存分开；安装目录不与 state 嵌套，不覆盖已有环境，不自动安装系统软件、下载模型或启动推理。
- ComfyUI 使用固定版本和发行包哈希的候选依赖锁；IndexTTS 固定上游提交及 uv.lock。依赖锁生成、模块导入和真实 GPU 验收分别记录，不能互相替代。
- 页面预览计划后才显式安装，参数变更使原计划失效；执行中显示阶段并可取消，CLI 使用相同内部实现。清理完成后才报告取消，失败保留阶段/日志并使用新目录重试。服务重启不自动续装。
- 标准方案已通过上海二 A 无卡模式下全新独立环境的依赖安装、一致性与基础导入检查（ComfyUI 87 包、IndexTTS 142 包）；新环境 GPU 样本已另行验收，既有托管模式样本不替代本次验收；全新基础实例部署单独记录。开发机没有 GPU，本机 Windows/WSL 仅做轻量开发、协议/管理测试与网络检查，不进行大型推理依赖安装、模型加载或推理。验收放在云端，优先上海二 A、其次华北二 A；资源不足时不退回本机执行重任务。GPU 测试前通知，结束后关闭本轮启动的实例。此为开发运维流程，云购买不进入 Worker 功能，产品仍以有 GPU 的 Linux/WSL2 主机为支持目标。
- 安装方案不绑定特定 CUDA/Python 镜像名称。基础 CUDA/Python、PyTorch/Miniconda、已有 ComfyUI 镜像均可作为宿主候选，分别检查实际系统、解释器与工具。在新目录安装的独立推理环境不继承镜像中的任意 Torch 版本。GPU 缺货时，可用云端无卡模式继续依赖安装、基础导入和管理协议验收；不加载模型或做 CPU 推理。独立环境安装、复用服务、全新基础镜像部署与真实 GPU 推理分别记结果，不把前者标作后者，不重装或覆盖已有环境。
- 完整接口与状态见 Server docs/model-and-scheduling.md；本轮证据见 docs/worker-standard-install-acceptance-2026-09-27.md。媒体处理位置、任务协议和模型调度规则保持不变。

## 42. 独立语言模型双执行路径（2026-09-27）

- Server 统一选择互联网 API 或 Worker 语言模型，按精确规格路由，不以 HTTP 协议判断队列。API、GPU、Server FFmpeg 继续独立限流；媒体执行位置不变。

- 文本生成、主动提示词优化共用模型选择。原稿与建议并列，应用才替换；失败和取消不改原稿。图片优化携带操作类型，H3 固定规则修订与系统提示词随任务冻结，不引入积分。

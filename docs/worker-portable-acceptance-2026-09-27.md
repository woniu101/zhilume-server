# Worker 0.10 部署便利性与解耦验收

配套 Studio 0.13 / Server 0.10；任务协议维持 3.0。PRD v0.26。未新增语言模型执行器，未改变 Studio/Server 媒体执行位置。

## 实现

- Linux 发布包：wheel、统一安装脚本、版本激活/回退工具、配置模板；无须克隆开发仓库。程序版本目录与 state 分离，安装失败不可激活，运行中拒绝版本切换，wheel 哈希及依赖清单留档。
- Worker 托管 ComfyUI 与复用外部服务两种路径。Qwen/H3 通过 runtimeId 共用服务，部署路径与端口不进入公开模型规格。IndexTTS 继续按任务管理独立进程。
- 管理页/CLI 共用配置、检查、启动、等待停止和取消停止接口；管理鉴权与调度凭证分开。进程服务在线不等于模型可用或真实推理通过。
- 停止共享服务先禁止全部消费者接单，再等待/取消任务；仅回收本 Worker 创建的进程组，不接管占用端口。GPU 隔离标记不能靠重启服务绕过，仅原服务可启动用于恢复。
- 通用 Linux 模型路径模板与平台公共软链接分开。提供控制服务容器模板及上下文白名单，未冒充完整推理镜像。

## 验收证据

- Windows Worker 全套 40 项：36 通过、4 项平台相关跳过，包括新增运行服务权限、坏配置隔离、共享停止和隔离恢复检查。
- WSL2 Ubuntu 22.04 部署专项 7/7：真实 CPU HTTP 测试服务启动、进程组回收、取消未就绪启动、占用端口不接管、服务运行锁与版本回退。测试 HTTP 服务模拟 ComfyUI 健康接口，不加载模型。
- `deploy/accept-portable.py` 在临时全新程序和数据目录分别安装 0.9.0 与 0.10.0 wheel：无 Torch/Pillow 核心可启动，静态页面可用；无 Server 绑定管理可用；服务运行时回退被拒绝；停服务后升级回退成功，workerId、任务凭证与管理凭证文件哈希不变。
- Studio `e2e/worker-management.spec.ts`：真实 Worker 管理页、深浅主题、窄屏宽度、托管服务配置保存、两种服务模式选择、模型 JSON 关联、缺程序提示与原有环境/权限/诊断流程。测试素材为临时路径，无真实凭证出现在证据中。

## 仍需 GPU / 外部环境验收

后续同日已完成上海二 A 托管模式真实 GPU 验收：Qwen→IndexTTS→H3 切换、视频取消并停止共享服务、显存释放、再次生成、正常重启及身份保留。见 [托管 GPU 验收记录](worker-managed-gpu-acceptance-2026-09-27.md)。复用已有推理环境，没有下载模型或重装 GPU 依赖；本轮启动的实例已关闭。

尚未验收：全新 CUDA 依赖安装、其他云平台和自有 GPU 主机、容器构建及 GPU 映射、华北二 A，以及硬崩溃和运行中等待自然结束再停服。本次样本不能替代这些验收。

托管服务默认显式启动，Worker 重启后不自动重跑任务或加载模型。当前依赖清单是安装溯源，不是已经认证的完整 CUDA 锁文件。未来版本数据格式不兼容时不承诺任意版本回退。

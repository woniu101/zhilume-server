## 上海二 A RTX 5090 针对性实测

使用现有 14 vCPU / 48 GiB / 5090 32 GiB 实例，程序安装新目录、保留独立 state，复用现有 ComfyUI 和 IndexTTS Python/模型环境；未下载模型权重。Qwen 的三个权重组件及 IndexTTS 主要模型文件现场计算 SHA-256 后声明身份。

ComfyUI 固定提交 `79be670e2d9be63e238785af307369d2b9039ed1`，IndexTTS 固定既有 2.5 环境。Worker 核心仅安装自身依赖和显式 image/Pillow 适配依赖，不重复安装推理环境。

| 场景 | 结果 |
|---|---|
| Qwen 2512，512×512 / 5 步，PNG | 成功，315283 字节，经 Server 哈希核验归档 |
| 同 Worker 第二个图片任务 | 排队，未执行 GPU 即可取消 |
| 图片后切换 IndexTTS 中文合成 | 成功，124352 字节 WAV，独立进程结束后归档 |
| 返回图片执行器，1024×1024 / 50 步任务取消 | 确认停止后 cancelled，无输出归档 |
| 每次 GPU 任务释放后 | nvidia-smi 实际占用均约 778 MiB，回到本机空载范围 |
| 推理期间管理查询 | 8 次采样约 212–323 ms；管理接口未等待推理完成 |
| Server 无监听端口 | 仍可主动连接 Worker、传入素材、取回并归档结果 |
| 升级程序目录并重启 | Worker ID、两类凭证、Server 绑定均保留 |
| 无 Server 连接时注入单个执行器错误 | video 检查明确失败，image/speech 保持 ready，管理/诊断继续可用；随后恢复 video 为停用配置 |

首次 GPU 试验暴露真实缺陷：只检查 Torch active bytes 会在 ComfyUI 异步卸载尚未完成时提前放行，此时设备仍占约 20 GiB。修复后同时核对物理显存占用和框架占用，连续两次满足空载上限才清除资源锁/标记；新增回归测试覆盖“框架占用很小、物理占用仍很大”的场景。上表是修复后的完整复测结果，首次结果不作通过证据。

部署默认空载上限 1536 MiB，可显式设置 idleVramLimitMiB 为 256–4096 MiB；超过上限或无法获得有效设备统计时失败关闭，不宣称显存已释放。它是释放确认阈值，不是显存预测或抢占调度。

原始脱敏数据见 [GPU 验收数据](evidence/foundation-2026-09-27.json)。显式真实运行脚本为 `scripts/accept-foundation.mjs --execute`，凭证仅通过环境变量提供。实例测试后已确认 Stopped，保留已准备的程序和模型环境供下次继续。
